# 完整用户故事

优先级：P0 为首个可用版本必须完成；P1 为紧随其后的产品闭环；P2 为扩展。

## Epic A：安全接入

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| A1 | P0 | 作为用户，我希望输入 Token Plan Key 并立即验证，以便知道配置是否正确。 | 不回显完整 Key；显示连接结果、区域和错误摘要；日志不含鉴权头。 |
| A2 | P0 | 作为用户，我希望 Key 安全保存，以便重启后无需重新输入。 | Windows 使用系统凭据能力；数据库只保存 credential reference。 |
| A3 | P0 | 作为用户，我希望看到每类能力的实测状态，以免把“官方列出”误认为“当前 Key 可用”。 | 图片、视频、语音、声音复刻分别显示 documented/probe/verified/unavailable。 |
| A4 | P1 | 作为用户，当 Token Plan 不支持某项语音能力时，我希望添加普通百炼 Key。 | 两类凭据独立命名；路由选择透明；不自动把任务切到其他付费凭据。 |

## Epic B：模型发现与选择

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| B1 | P0 | 作为用户，我希望按图片、视频、语音和声音复刻浏览模型。 | 分类、搜索和可用性筛选均可用。 |
| B2 | P0 | 作为用户，我希望选择模型时看到官方说明。 | 显示来源链接、验证日期、能力与参数；内容为简短转述。 |
| B3 | P0 | 作为用户，我希望看出信息是否过期。 | 超过刷新策略的条目显示 stale，不再显示“已验证”。 |
| B4 | P0 | 作为用户，我希望测试模型后设为默认。 | 测试成功才能设为 verified default；失败保留错误和 request/task ID。 |
| B5 | P1 | 作为用户，我希望比较同类模型。 | 对比输入、输出、时长、分辨率、同步模式与凭据要求，不虚构价格。 |

## Epic C：图片

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| C1 | P0 | 作为用户，我希望输入提示词并测试图片模型。 | 根据模型 Schema 显示 size 等参数；结果立即下载到产物库。 |
| C2 | P1 | 作为用户，我希望 Agent 调用图片生成并获得本地文件。 | MCP 返回 artifact ID、路径、mime 和 manifest；不只返回临时 URL。 |
| C3 | P2 | 作为用户，我希望使用参考图或编辑图片。 | 模型明确支持时才展示上传入口；输入图进入私有上传区。 |

## Epic D：视频

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| D1 | P0 | 作为用户，我希望生成文生视频并看到实时状态。 | 提交后持久化 task ID；显示排队/运行/成功/失败/超时。 |
| D2 | P0 | 作为用户，我希望重启后继续追踪视频任务。 | 重启服务后从数据库恢复轮询，不重复提交任务。 |
| D3 | P0 | 作为用户，我希望下载完成后仍可访问视频。 | 临时 URL 立即下载，本地文件与哈希写入 manifest。 |
| D4 | P1 | 作为用户，我希望选择是否保留模型生成的音轨。 | 若供应商不支持无声参数，UI 明示“下载后本地移除音轨”。 |
| D5 | P2 | 作为用户，我希望使用首帧、首尾帧或参考素材生成视频。 | 只对支持 i2v/r2v 的模型展示对应上传和参数。 |

## Epic E：语音合成与声音复刻

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| E1 | P0 | 作为用户，我希望选择系统音色试听文本。 | 输出立即本地化；记录语言、模型、音色和文本。 |
| E2 | P0 | 作为声音所有者，我希望在明确授权后克隆声音。 | 必须勾选授权声明；创建 consent record；未授权不提交。 |
| E3 | P0 | 作为用户，我希望给克隆音色设置本地别名。 | voice ID 不在普通日志中显示；别名可用于后续合成。 |
| E4 | P0 | 作为用户，我希望系统防止模型不匹配。 | 克隆 target model 与合成 model 必须一致，否则前置拒绝。 |
| E5 | P1 | 作为用户，我希望管理和删除声音引用。 | 可删除本地别名/样本；远端删除能力若不可用必须明确说明。 |
| E6 | P2 | 作为用户，我希望按角色清单生成多角色对白。 | 分段生成、失败续跑、统一采样率并输出合并 manifest。 |

## Epic F：产物与历史

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| F1 | P0 | 作为用户，我希望在一个页面查看所有中间产物。 | 图片、视频、音频、音色按类型/日期/作业筛选。 |
| F2 | P0 | 作为用户，我希望知道产物由什么生成。 | 详情页显示模型、参数、来源、时间、哈希和上游 artifact。 |
| F3 | P0 | 作为用户，我希望失败也留下证据。 | 保存错误分类、request/task ID 和重试建议，不保存敏感响应头。 |
| F4 | P1 | 作为用户，我希望清理本地数据。 | 删除前显示影响范围；数据库和文件使用可验证的一致性流程。 |
| F5 | P1 | 作为用户，我希望导出一个可迁移任务包。 | 导出 manifest 与选择的产物；默认不包含 Key 和声音样本。 |

## Epic G：Agent 安装与调用

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| G1 | P0 | 作为 Codex 用户，我希望一键安装 Plugin/Skill 和 MCP。 | 安装器生成可审阅配置；在新会话中可见工具；支持卸载。 |
| G2 | P0 | 作为 Claude Code 用户，我希望安装 Skill/Command 与 MCP。 | 项目级和用户级安装可选；不把 Key 写进 Markdown。 |
| G3 | P0 | 作为 Kimi Code CLI 用户，我希望通过 Plugin 或 `mcp.json` 接入。 | 支持 stdio/HTTP MCP；显示连接状态；默认保留高风险操作审批。 |
| G4 | P0 | 作为 Agent，我希望列出模型再调用生成工具。 | MCP Schema 稳定；错误包含可行动的状态码和 capability 信息。 |
| G5 | P1 | 作为其他工具作者，我希望直接使用 CLI/HTTP。 | CLI 输出机器可读 JSON；本地 HTTP 默认只监听 127.0.0.1。 |
| G6 | P1 | 作为用户，我希望查看哪个 Agent 发起了任务。 | job manifest 记录 client name、session hint 和调用入口，不依赖聊天 ID。 |

## Epic H：可靠性与治理

| ID | 优先级 | 用户故事 | 验收标准 |
|---|---:|---|---|
| H1 | P0 | 作为用户，我希望模型更新不会让 Skill 静默失效。 | 注册表有 Schema 校验、来源和过期状态；CI 拒绝无来源条目。 |

| H4 | P1 | 作为用户，我希望控制本地磁盘占用。 | 支持保留策略、大小统计和安全清理预览。 |
| H5 | P1 | 作为维护者，我希望兼容性可以回归测试。 | Codex、Claude Code、Kimi Code 的安装和 MCP smoke test 可自动执行。 |
